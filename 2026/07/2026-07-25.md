## 学んだこと

- 変数の値はメモリ上に保存されており、それぞれの保存場所にはメモリアドレスが割り当てられている。
- ポインタ変数とは、メモリアドレスを値として保存する変数である。
- ポインタに関連する用語には、次のようなものがある。

  * **ポインタ型**：どの型の変数を指すポインタなのかを表す型
  * **ポインタ値**：メモリアドレスを表す値
  * **ポインタ変数**：ポインタ値を保存する変数
- ポインタ変数は、次のように宣言する。

```c
int *p;
```

- `int *p;`と`int* p;`は、どちらも同じ意味になる。ただし、複数の変数を同時に宣言した際の誤解を避けるため、`int *p;`のように変数名側へ`*`を付けて書く方法が分かりやすい。

```c
int *p, value;
```

この場合、ポインタ変数なのは`p`だけであり、`value`は通常の`int`型変数になる。

- 宣言した時点で指し示す対象が決まっていないポインタには、意図しないメモリアドレスを使用しないよう、`NULL`を代入して初期化するとよい。

```c
int *p = NULL;
```

- 通常の変数に`&`演算子を付けると、その変数のメモリアドレスを取得できる。

```c
int value = 10;
int *p = &value;
```

- ポインタ変数の前に`*`演算子を付けると、そのポインタが指している場所に保存された値を読み書きできる。これは**間接参照**または**デリファレンス**と呼ばれる。

```c
*p = 20;
```

この処理を行うと、`p`が指している`value`の値も`20`に変更される。

- ポインタ変数に「2つのモード」があるわけではない。ポインタ変数そのものを使う場合はメモリアドレスを扱い、`*p`のように間接参照する場合は、そのアドレスに保存された値を扱う。
- C言語では、関数の引数はすべて値渡しである。ポインタを関数へ渡した場合も、渡されるのはメモリアドレスを表すポインタ値のコピーである。
- ただし、コピーされたポインタも呼び出し元と同じ変数を指しているため、関数内から呼び出し元の変数を変更できる。

```c
void change_value(int *p)
{
    *p = 20;
}
```

- この仕組みは参照渡しに似ているが、C言語には厳密な意味での参照渡しはなく、ポインタを値渡しすることで同様の処理を実現している。
- 配列名は、多くの式の中で配列の先頭要素を指すポインタへ変換される。

```c
int array[3] = {10, 20, 30};
int *p = array;
```

この場合、`p`は配列の先頭要素である`array[0]`を指す。

- 配列とポインタは同じものではない。配列は複数の要素を連続して確保した領域であり、ポインタはメモリアドレスを保存する変数である。ただし、配列名が先頭要素へのポインタとして扱われることが多いため、似た書き方ができる。
- 関数の引数に配列を書く場合、次の2つは実質的に同じ意味になる。

```c
int sum(int array[]);
int sum(int *array);
```

- 関数の仮引数として書いた配列の要素数は、関数には引き継がれない。

```c
int sum(int array[10]);
```

このように要素数を書いても、通常の関数引数では`int *array`として扱われる。そのため、配列の要素数は別の引数として渡す必要がある。

```c
int sum(int array[], int size);
```

- ポインタには加算や減算を行うポインタ演算があり、次の要素や前の要素へ移動できる。

```c
p++;
```

`int`型へのポインタであれば、`p++`によって次の`int`型要素を指すようになる。

- 以前は、配列の添字を使用するよりもポインタ演算を使用した方が高速になる場合があった。しかし、現在のコンパイラは最適化性能が高いため、まずは読みやすく安全なコードを書くことが重要である。
- 配列の添字を使った処理も、内部的にはポインタを利用した処理として解釈できる。

```c
array[i]
```

これは、次の式と同じ意味になる。

```c
*(array + i)
```

## つまずいたこと

- メモリアドレス、ポインタ変数、`&`演算子、`*`演算子など、新しい概念や記号が一度に多く登場した。
- 宣言時の`*`と、間接参照に使用する`*`は見た目が同じだが、役割が異なるため混乱した。
- 配列とポインタは同じような書き方ができるが、完全に同じものではない点が難しかった。
- 今回学んだ内容は、一度ですべて覚えるのではなく、実際にコードを書きながら少しずつ理解していきたい。

## 一言

* 現時点では、ポインタは「関数の外にある変数を変更したい場合や、配列を関数へ渡す場合に利用する仕組み」と考えると理解しやすそう。
* ただし、動的メモリ確保、文字列操作、データ構造、組込みシステム、OSなどを扱う場合には欠かせない機能になるため、今後も少しずつ慣れていきたい。
