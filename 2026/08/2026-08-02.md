## 学んだこと
SSH接続では、接続元と接続先を意識し、hostnameで現在操作しているVMを確認できる。
ssh.serviceを停止しても、ssh.socketが有効な場合は、接続要求をきっかけにSSHサービスが再起動することがある。
SSHサービスとソケットの両方を停止すると、SSH接続時にConnection refusedが表示された。
Connection refusedは、接続先のIPアドレスまでは到達しているが、対象ポートで待ち受けているサービスがない状態を示す。
journalctl -u sshを使うと、SSHサービスの開始・停止や認証失敗の記録を確認できる。
存在しないユーザーでSSH接続すると、ログにInvalid userやFailed passwordが記録される。
UFWを有効にすると、許可していない受信通信は遮断される。
UFWが有効でも、eth1のTCP 22番ポートを許可すれば、隔離ネットワーク経由のSSH接続が可能になる。

使用した主なコマンド
```text
ssh ユーザー名@10.77.0.10
hostname
exit

sudo systemctl stop ssh.service
sudo systemctl stop ssh.socket
sudo systemctl start ssh.socket

systemctl status ssh.service
systemctl status ssh.socket

sudo journalctl -u ssh --since "15 minutes ago"

sudo ufw enable
sudo ufw allow in on eth1 to any port 22 proto tcp
sudo ufw status numbered
```

## つまずいたこと
- ssh.serviceを停止したにもかかわらず、SSH接続するとサービスが再開した。
- 原因はssh.socketが接続待ちを続けていたためだった。
- UFWを有効化した後、SSH接続ができなくなった。
- eth1のTCP 22番ポートを許可していなかったことが原因だった。
- 許可ルールを追加したところ、UFWを有効にしたままSSH接続できた。
