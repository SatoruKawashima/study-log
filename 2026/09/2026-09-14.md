# 2026-09-14 Linuxサーバー運用・監視ラボ 学習記録（SSH公開鍵認証・Nginx自動復旧・healthcheck）

## 日付

2026-09-14

## やったこと

- `lab-client01` で Ed25519 鍵を新規作成し、`ssh-copy-id` で `lab-target01` に公開鍵を登録。
- 公開鍵認証でパスワードなしに SSH 接続できることを確認。
- `/etc/ssh/sshd_config.d/00-lab-hardening.conf` に `PasswordAuthentication no` を設定し、鍵認証は通る一方、パスワード認証は拒否されることを確認。
- Nginx の systemd override に `Restart=on-failure` と `RestartSec=3s` を設定。
- Nginx のメインプロセスを異常終了させ、数秒後に自動復旧することを確認。
- `healthcheck.sh` を再作成し、日時・ホスト名・Nginx 状態・ディスク使用量・メモリ使用量・load average を出力するようにした。
- cron で `healthcheck.sh` を5分ごとに実行し、`healthcheck.log` に追記されることを確認。
- `logrotate` の設定を作成し、日次・7世代・圧縮・`rew` 所有でログを管理するようにした。
- `logrotate -d` で設定確認、`logrotate -f` で強制ローテーションを実施。
- `logrotate.timer` が `active (waiting)` であることを確認。

- ping-tでASW SAAのセキュリティ分野の問題を10問だけ解答

## 理解したこと

- SSH の公開鍵認証では、クライアント側に秘密鍵、サーバー側に公開鍵を置き、対応する鍵で本人確認を行う。
- `PasswordAuthentication no` にしても、公開鍵認証が正しく設定されていれば SSH 接続は継続できる。
- systemd の `Restart=on-failure` により、サービスの異常終了時だけ自動再起動させられる。
- `>>` はファイル末尾への追記で、ログを蓄積する用途に向いている。
- `tail` はファイル末尾の内容を見るコマンドで、最新ログの確認に使いやすい。
- cron は healthcheck の定期実行、logrotate は増え続けるログの世代管理、systemd timer は logrotate の定期起動を担当している。

## つまずき

- `tail` の意味を理解しておらず、cron の追記ができていないと思ったが、実際には `healthcheck.log` に正常に追加されていた。

- AWSとはいえセキュリティ問題なら簡単だと思ったが、やはりAWS自体のサービスへの知識が足りていなかった。
