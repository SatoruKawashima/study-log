## Detecting Web Shells

Web Shellの基本と、その検知方法について学習した。

Web Shellは、WebアプリケーションやWebサーバーの脆弱性を悪用して設置され、その後の遠隔操作や永続化に利用される可能性がある。

MITRE ATT&CKの観点では、単なるInitial Accessだけではなく、侵害後のPersistenceなど複数の段階に関係することを確認した。

検知方法としては、

- Webサーバーログ
- ファイルシステム上の不審なファイル
- ネットワークトラフィック

など複数の情報源を確認する必要がある。

また、Wiresharkを利用し、Web Shellとの通信がネットワーク上でどのように見えるのかについても確認した。

### 学び

Web Shellは「怪しいファイルを探す」だけでは不十分であり、

**どのように侵入されたか  
→ どこにファイルが設置されたか  
→ その後どのような通信・操作が行われたか**

という形で、複数の証跡を関連付けて調査する必要があると感じた。

## Detecting Web DDoS

DoS / DDoS攻撃の基本から、ログを利用した検知、対策まで学習した。

Webサーバーログから大量アクセスや不自然なリクエスト傾向を確認し、Splunkを利用した分析も行った。

### 狙われやすいエンドポイント

DDoSでは単純に大量のリクエストを送るだけでなく、サーバー側で処理負荷の高いエンドポイントを狙うことで、より少ない通信でもリソースを消費させられる場合がある。

例として以下のようなエンドポイントを確認した。

- `/login`
  - 認証処理が必要
- `/search`
  - 複雑なDBクエリが発生する可能性がある
- `/api`
  - 動的コンテンツ生成などの処理を伴う
- `/register` / `/signup`
  - 入力検証やDBへの書き込みが必要
- `/contact` / `/feedback`
  - DB登録やメール送信処理が発生する可能性がある
- `/cart` / `/checkout`
  - セッション管理、在庫確認、決済処理など複数の処理が発生する

そのため、ログ分析では単純なリクエスト数だけでなく、**どのURIにアクセスが集中しているか**を見ることも重要だと感じた。

### 対策

アプリケーション側では、

- 適切な入力検証
- Bot対策などのChallengeの実装
- 高負荷な処理を無制限に実行させない設計

などを検討する。

また、Webサーバーやネットワーク側では、

- CDN
- WAF
- ISPやクラウド事業者が提供するDDoS対策サービス

などを利用し、アプリケーションへ到達する前の段階で攻撃トラフィックを吸収・遮断することも重要である。

### 学び

DDoS対策はアプリケーションだけで完結するものではなく、CDNやWAF、上流ネットワークなどを組み合わせた多層的な対策が必要だと理解した。

## Windows Logging for SOC

Windowsのシステムログを利用し、脅威を検知・調査する方法について学習した。

Windows Event Viewerなどを利用し、認証やアカウント操作に関係するイベントを確認した。

### 主なEvent ID

認証関連では、

- **4624**：ログオン成功
- **4625**：ログオン失敗
- **4634 / 4647**：ログオフ
- **4648**：明示的な資格情報を利用したログオン
- **4672**：特別な権限が割り当てられたログオン

などを確認した。

アカウント管理関連では、

- **4720**：ユーザーアカウント作成
- **4728 / 4732**：グループへのメンバー追加
- **4740**：アカウントロックアウト

などを確認した。

これらのログを利用することで、

- ブルートフォース攻撃
- 不審なアカウント作成
- 特権アカウントの利用
- グループメンバーシップの変更

などを調査できる。

### Sysmon

Sysmonを利用し、通常のWindows Event Logより詳細なシステム活動を記録・調査する方法について学習した。

プロセス実行やネットワーク接続など、インシデント調査に有用な情報を収集できることを確認した。

### PowerShellログ

PowerShellのログについても調査し、不審なスクリプトやコマンド実行を確認する方法を学習した。

### 所感

WindowsのログはEvent IDの種類が多く、すべてを暗記するのは難しいと感じた。

そのため、番号そのものを覚えるというよりも、

- 認証
- アカウント管理
- 特権操作
- プロセス実行
- PowerShell実行

など、**調べたい行動ごとにどのログを見るべきか整理することが重要**だと感じた。

以前取り組んだInvestigating Windowsでは「どこを調べればよいのか」が分からず苦戦したが、今回の学習を通じて、Windows上に残る証跡と調査ポイントについて少しずつ整理できるようになってきた。

## ひとこと

今回はWeb Shell、DDoS、Windowsログとテーマは異なっていたが、どのRoomでも共通して、

**「攻撃が起きた場合、どこにどのような証跡が残るのか」**

を考えることが重要だった。

SOCの学習が進むにつれて、単に攻撃手法を知るだけでなく、ログ・ファイル・ネットワークなど複数の情報源から侵害の痕跡を探すことが中心になってきたと感じる。
