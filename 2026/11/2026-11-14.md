## File and Hash Threat Intel

ファイルやハッシュ値を起点としてThreat Intelligenceを収集し、疑わしいファイルについて分析する方法を学習した。

### ファイル情報の確認

まず、調査対象となるファイルについて、

- ファイル名
- ファイルパス
- ハッシュ値

などを確認した。

特に、通常とは異なる保存場所や、正規ファイルに似せた名称などは、より詳しく調査するための手掛かりになる。

また、分析を始める前に対象ファイルとハッシュ値が一致していることを確認し、正しいArtefactを調査していることを保証する必要がある。

### Threat IntelligenceによるEnrichment

取得したハッシュ値を利用し、

- VirusTotal
- MalwareBazaar
- Hybrid Analysis

などの情報源から追加情報を調査した。

ハッシュから既知のマルウェア情報を確認するだけでなく、SandboxのTelemetryから、

- 実行されたCommand
- Child Process
- Network Connection
- Persistenceに関係する挙動
- MITRE ATT&CK Technique

などを確認する方法を学んだ。

ただし、各サービスは情報量が多く、現時点では「どこを確認するべきなのか」で迷うことも多かった。

教材で使用されている画面と現在のWebサイトのUIが変わっている場合もあり、必要な情報そのものを探すことに苦戦する場面もあった。

### 学び

実務では「このCommandを探せ」「このTechniqueを確認せよ」といった明確な指示が最初から存在するとは限らない。

そのため、単に既知マルウェアとして登録されているかを見るだけでなく、

**File  
→ Behavior  
→ Network  
→ Persistence  
→ Scope**

という観点から、調査対象が実際に何をしたのかを整理する必要があると感じた。

MITRE ATT&CKについても、最初からTechniqueを探すというより、確認できた挙動を整理した後で共通言語としてマッピングする使い方を意識したい。

## IP and Domain Threat Intel

IPアドレスやDomainを起点として、Open Source Threat Intelligenceを利用して情報をEnrichmentする方法について学習した。

主に以下の情報源やデータを確認した。

- WHOIS / RDAP
- Domain Age
- DNS Record
- TLS Certificate
- ASN
- Geolocation
- VirusTotal
- Shodan
- Censys
- IP2Proxy
- Spur

### DomainとIPの調査

WHOISやRDAPを利用してDomainの登録情報や作成時期を確認した。

作成されてから間もないDomainなどは、PhishingやMalware Campaignで利用される可能性を考えるための判断材料になる。

また、DNS RecordやTLS Certificate、ASNなどを確認することで、

- どのNetworkに属しているか
- どのようなInfrastructure上で動作しているか
- 他の関連するDomainやServiceが存在するか

などの追加情報を得られる。

ShodanやCensysからはInternet上に公開されているServiceの情報を確認し、IP2ProxyやSpurなどからVPN、Proxy、Tor Exit Nodeなどの可能性を確認した。

### 単一の情報を信用しない

今回特に重要だったのは、

**単一の情報源や判定結果だけで悪性と判断しないこと**

だった。

Domain Age、ASN、Geolocation、公開Service、Reputationなどを複数の情報源から確認し、相関させて判断する必要がある。

また、Threat Intelligenceの情報は時間経過によって変化する可能性があるため、今回の演習では提供された時点のデータを利用して分析を行った。

### CDNについて感じた疑問

作成直後のDomainなど、分かりやすい特徴が存在する場合は比較的疑いやすい。

一方、Threat ActorがCDNや正規Cloud Serviceなどを利用した場合、共有IP上に正規Serviceと悪性Serviceが混在する可能性があり、IP Reputationだけでは判断しにくくなる。

そのような場合には、

- Domain自体の履歴
- DNS情報
- Certificate
- URL
- 通信元Process
- 通信頻度やPattern
- 他のIOCとの関連

など、IP以外のContextも含めて判断する必要があると感じた。

## Challenge: Invite Only

これまで学習したFile、Hash、IP、Domain Threat Intelligenceを利用する総合Challengeに取り組んだ。

SOCのL1 AnalystからEscalationされた、

- Suspicious IP
- Suspicious File Hash

を起点として追加調査を行い、利用可能なThreat Intelligenceへ整理した。

### 調査の流れ

まず、提供されたIPとHashについて外部情報を利用してEnrichmentした。

そこから関連する、

- URL
- Domain
- File
- Network Infrastructure
- Malware Behaviour

などを調査し、それぞれのArtefactの関連性を確認した。

単純に、

**「このIPは悪性」  
「このHashはMalware」**

と判断して終わるのではなく、それぞれの情報を関連付けて「どのような攻撃が行われていたのか」を整理した。

最終的には、Discordの期限切れInvite Linkを乗っ取り、利用者をClickFix系の手法へ誘導するCampaignに関連していることを確認した。

### 学び

このChallengeを通じて、

**IOC  
→ Enrichment  
→ Correlation  
→ Attack Story  
→ Usable Threat Intelligence**

という一連の流れを体験できた。

Threat Intelligenceでは、個別のIOCを集めるだけでなく、それぞれを関連付け、

- 何が起きているのか
- どのようなAttack Techniqueなのか
- どのIndicatorを監視すべきか
- 防御側がどのような対応を取れるのか

まで整理することが重要だと感じた。

## 所感

今日はFile / Hash、IP / Domainを起点としたThreat Intelligenceの調査を行い、最後にInvite Onlyで総合的な分析を行った。

今回の一連の学習を通じて、

**「IOCそのもの」と「Threat Intelligence」は同じではない**

ことが特に印象に残った。

HashやIP、Domainはあくまで調査の入口であり、それらを外部情報でEnrichmentし、挙動やInfrastructure、他のIndicatorと関連付けることで、初めて判断や対応に利用できる情報になる。

一方で、各Threat Intelligence Platformには非常に多くの情報が存在するため、

**「何を見るべきか」  
「どの情報を切り取るべきか」**

についてはまだ迷うことが多い。

今後は単にサイト上の情報を探すのではなく、

**何者なのか  
何をしたのか  
どこと通信したのか  
どのようにPersistenceしたのか  
他の端末やIndicatorにも影響があるのか**

という問いを立ててから、必要な情報を探すことを意識したい。
