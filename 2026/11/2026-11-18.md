## Incident Handling With Splunk

Splunkを利用してインシデントを調査し、攻撃者の行動をCyber Kill Chainに沿って整理する方法を学習した。

今回のScenarioでは、Wayne EnterpriseのWebサイト `imreallynotbatman.com` が改ざんされるまでの攻撃活動を追跡した。

### Reconnaissance

Web Serverに対するScanning Activityを確認し、攻撃元IPや利用Toolを特定した。

- 攻撃元IPを確認
- AcunetixによるWeb Scanを特定

単に不審なアクセスを見るだけでなく、Reconnaissance段階として位置付けることで、攻撃の初期活動として整理した。

### Exploitation

次にBrute-force Attackの痕跡を調査した。

多数の認証試行の中から成功したアクセスを確認し、攻撃者が実際に侵入へ成功したことを確認した。

### Installation

Sysmon Logなどを確認し、攻撃者によってUploadされた不審なExecutableを特定した。

- `3791.exe`
- File Hashの確認

Host側のLogからFile実行や生成の痕跡を追うことで、侵害後の活動を調査した。

### Action on Objective

攻撃者がWeb Serverを侵害した後、Web Siteを改ざんしたことを確認した。

Logから改ざんに利用されたFileを特定し、攻撃の目的達成までの流れを確認した。

### Weaponization / Delivery

Threat Intelligence Platformを利用し、攻撃に関連する、

- Domain
- IP Address
- Email Address
- Malware

などを調査した。

既知のIOCを起点に、攻撃者Infrastructureや関連Malwareを調査することで、Splunk内部のLogだけでは分からない情報を補完した。

### 学び

今回のRoomでは、

**Reconnaissance  
→ Exploitation  
→ Installation  
→ Action on Objective**

という攻撃の進行をCyber Kill Chainに沿って整理した。

また、Splunk LogだけでなくOSINTやThreat Intelligenceを組み合わせることで、攻撃者の活動をより広く把握できることを学んだ。

単発のEventを見るのではなく、

**「このEventは攻撃のどの段階なのか」**

と考えながら調査することで、攻撃全体を整理しやすくなると感じた。

## Challenge: Benign

Splunkを利用し、侵害された可能性のあるWindows HostのProcess Execution Logを調査した。

今回利用できたLogは主にEvent ID 4688で、Process Creationの記録を中心に分析した。

### 調査内容

不審なProcess ExecutionやCommand Lineを確認し、

- 正規ユーザー・Processに似せたなりすまし
- `certutil.exe`の不審利用
- 外部からProgramを取得するCommand
- 攻撃者が利用していたUploader

などを確認した。

最終的には、不審なCommand Lineから利用Toolを追跡し、Flagを発見した。

### 学び

今回のChallengeは難易度自体は高くなかったが、

**Process  
→ Command Line  
→ Tool  
→ 実際の目的**

という流れで調査する練習になった。

特に`certutil.exe`のような正規Windows Toolは通常用途にも利用されるため、

**Tool名だけではなく、どのようなArgumentで実行されているか**

を見る必要がある。

Event ID 4688だけでもCommand Line情報が取得できていれば、不審な挙動をかなり追跡できることを確認した。

## Challenge: Tempest

侵害されたWorkstationに対し、Endpoint LogとNetwork Logを組み合わせてFull Attack Chainを調査するChallengeに取り組んだ。

今回のRoomでは、これまで利用経験の少ないToolが多数登場した。

### Event Correlation

複数のLog Sourceから取得したArtifactを関連付け、攻撃Scenarioを再構成する方法について学習した。

例えばNetwork Connectionについても、

- Firewall / Packet Capture
- Sysmon Event ID 3
- Windows Event Log

など、異なるSourceから情報を取得できる。

それぞれから、

- Source / Destination IP
- Port
- Protocol
- Process Name
- User Account
- Machine Name
- Timestamp

を関連付けることで、単一のLog Sourceだけでは見えない攻撃の全体像を再構成できる。

### Endpoint Analysis

Windows Event LogやSysmon Logを調査するために、

- EvtxECmd
- Timeline Explorer
- SysmonView
- Event Viewer

を利用した。

特にEvtxECmdを利用してEVTX Fileを解析しやすいCSV形式へ変換し、Timeline Explorerで時系列に並べて調査した。

そこから、

- 不審なFile
- URL
- Query
- Process Activity

などを確認した。

### Network Analysis

Network側では、

- Wireshark
- Brim

を利用した。

Brimで大量の通信から不審なTrafficの候補を探し、その後Wiresharkで詳細を確認するという使い方を学んだ。

現時点では両Toolの役割を完全には使い分けられていないが、

**Brimで広く検索  
→ Wiresharkで細部を確認**

という流れを経験した。

### 難しかった点

今回登場したToolの多くが初見だったため、調査そのものよりもToolの使い方で詰まる場面が多かった。

そのため、かなりWriteupを参考にしながら進めた。

ただし今回の目的としては、

- EvtxECmd
- Timeline Explorer
- SysmonView
- Brim

などの存在と役割を知ることができた点は大きかった。

## 所感

今回はSplunkを利用したIncident Handlingから始まり、Windows Process Logの調査、最後にEndpoint / Network Logを横断したDFIR寄りのChallengeまで取り組んだ。

特に共通していたのは、

**単一のEventやLogだけで判断しないこと**

だった。

SplunkではCyber Kill Chainに沿って攻撃の各Phaseを整理し、BenignではProcessとCommand Lineを関連付け、TempestではEndpointとNetworkの複数Sourceを相関させた。

今回の学習を通じて、

**Artifactを見つける  
→ 関連するArtifactを探す  
→ TimestampやProcess、IPなどでつなぐ  
→ 攻撃のStoryを再構成する**

という調査の流れがより明確になった。

一方で、新しいToolが多く登場すると、分析以前に操作方法で詰まりやすいことも実感した。

現時点ではすべてのToolを使いこなす必要はなく、

**「何を調べるためのToolなのか」**

を覚え、必要になった際に調べながら利用できるようにしたい。
