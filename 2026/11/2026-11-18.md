## Incident Handling With Splunk

Splunkを利用してインシデントを調査し、攻撃者の行動をサイバーキルチェーンに沿って整理する方法を学習した。

今回のシナリオでは、Wayne EnterpriseのWebサイト `imreallynotbatman.com` が改ざんされるまでの攻撃活動を追跡した。

### 偵察

Webサーバーに対するスキャン活動を確認し、攻撃元IPや利用ツールを特定した。

- 攻撃元IPを確認
- AcunetixによるWeb Scanを特定

単に不審なアクセスを見るだけでなく、偵察段階として位置付けることで、攻撃の初期活動として整理した。

### 攻撃

次にブルートフォース攻撃の痕跡を調査した。

多数の認証試行の中から成功したアクセスを確認し、攻撃者が実際に侵入へ成功したことを確認した。

### インストール

Sysmon logなどを確認し、攻撃者によってアップロードされた不審なExecutableを特定した。

- `3791.exe`
- File Hashの確認

Host側のログからFile実行や生成の痕跡を追うことで、侵害後の活動を調査した。

### 目的の実行

攻撃者がWebサーバーを侵害した後、Web Siteを改ざんしたことを確認した。

ログから改ざんに利用されたFileを特定し、攻撃の目的達成までの流れを確認した。

### 武器化 / 配送

Threat Intelligence Platformを利用し、攻撃に関連する、

- Domain
- IP Address
- Email Address
- Malware

などを調査した。

既知のIOCを起点に、攻撃者インフラや関連マルウェアを調査することで、Splunk内部のログだけでは分からない情報を補完した。

### 学び

今回のRoomでは、

**偵察  
→ 攻撃  
→ インストール  
→ 目的の実行**

という攻撃の進行をサイバーキルチェーンに沿って整理した。

また、Splunk logだけでなくOSINTやThreat Intelligenceを組み合わせることで、攻撃者の活動をより広く把握できることを学んだ。

単発のイベントを見るのではなく、

**「このイベントは攻撃のどの段階なのか」**

と考えながら調査することで、攻撃全体を整理しやすくなると感じた。

## Challenge: Benign

Splunkを利用し、侵害された可能性のあるWindows HostのProcess Execution logを調査した。

今回利用できたログは主にEvent ID 4688で、Process Creationの記録を中心に分析した。

### 調査内容

不審なProcess ExecutionやCommand Lineを確認し、

- 正規ユーザー・Processに似せたなりすまし
- `certutil.exe`の不審利用
- 外部からProgramを取得するCommand
- 攻撃者が利用していたUploader

などを確認した。

最終的には、不審なCommand Lineから利用ツールを追跡し、Flagを発見した。

### 学び

今回のChallengeは難易度自体は高くなかったが、

**Process  
→ Command Line  
→ ツール  
→ 実際の目的**

という流れで調査する練習になった。

特に`certutil.exe`のような正規Windows Toolは通常用途にも利用されるため、

**ツール名だけではなく、どのようなArgumentで実行されているか**

を見る必要がある。

Event ID 4688だけでもCommand Line情報が取得できていれば、不審な挙動をかなり追跡できることを確認した。

## Challenge: Tempest

侵害されたWorkstationに対し、エンドポイントログとネットワークログを組み合わせてFull Attack Chainを調査するChallengeに取り組んだ。

今回のRoomでは、これまで利用経験の少ないToolが多数登場した。

### Event Correlation

複数のログソースから取得したArtifactを関連付け、攻撃シナリオを再構成する方法について学習した。

例えばNetwork Connectionについても、

- Firewall / Packet Capture
- Sysmon Event ID 3
- Windows Event log

など、異なるソースから情報を取得できる。

それぞれから、

- ソース / Destination IP
- Port
- Protocol
- Process Name
- User Account
- Machine Name
- Timestamp

を関連付けることで、単一のログソースだけでは見えない攻撃の全体像を再構成できる。

### エンドポイント分析

Windows イベント ログやSysmon ログを調査するために、

- EvtxECmd
- Timeline Explorer
- SysmonView
- Event Viewer

を利用した。

特にEvtxECmdを利用してEVTX Fileを解析しやすいCSV形式へ変換し、Timeline Explorerで時系列に並べて調査した。

そこから、

- 不審なFile
- URL
- Query
- Process Activity

などを確認した。

### ネットワーク分析

ネットワーク側では、

- Wireshark
- Brim

を利用した。

Brimで大量の通信から不審なTrafficの候補を探し、その後Wiresharkで詳細を確認するという使い方を学んだ。

現時点では両ツールの役割を完全には使い分けられていないが、

**Brimで広く検索  
→ Wiresharkで細部を確認**

という流れを経験した。

### 難しかった点

今回登場したツールの多くが初見だったため、調査そのものよりもツールの使い方で詰まる場面が多かった。

そのため、かなりWriteupを参考にしながら進めた。

ただし今回の目的としては、

- EvtxECmd
- Timeline Explorer
- SysmonView
- Brim

などの存在と役割を知ることができた点は大きかった。

## 所感

今回はSplunkを利用したIncident Handlingから始まり、Windows Process ログの調査、最後にエンドポイント / ネットワーク ログを横断したDFIR寄りのChallengeまで取り組んだ。

特に共通していたのは、

**単一のイベントやログだけで判断しないこと**

だった。

Splunkではサイバーキルチェーンに沿って攻撃の各フェーズを整理し、BenignではProcessとCommand Lineを関連付け、Tempestではエンドポイントとネットワークの複数ソースを相関させた。

今回の学習を通じて、

**Artifactを見つける  
→ 関連するArtifactを探す  
→ TimestampやProcess、IPなどでつなぐ  
→ 攻撃のStoryを再構成する**

という調査の流れがより明確になった。

一方で、新しいツールが多く登場すると、分析以前に操作方法で詰まりやすいことも実感した。

現時点ではすべてのツールを使いこなす必要はなく、

**「何を調べるためのツールなのか」**

を覚え、必要になった際に調べながら利用できるようにしたい。
