## Splunk: Setting up a SOC Lab

Splunkを利用したSOC環境の構成と、ログをSplunkへ取り込むまでの基本的な仕組みについて学習した。

これまでSplunkでは主にSPLを使ったログ検索やインシデント調査を行ってきたが、今回はその前段となる、

**「ログがどのようにSplunkへ届き、検索できる状態になるのか」**

を実際に構築しながら確認した。

### Splunkの主な構成要素

Splunk環境では、主に以下のコンポーネントが利用される。

#### Forwarder

端末やサーバーへ導入し、ログをSplunkへ転送する。

Universal Forwarderは軽量なログ転送を担当し、Heavy Forwarderでは転送前に解析やフィルタリングなどの処理を行うこともできる。

#### Indexer

Forwarderなどから受信したログを処理し、Indexへ保存する。

保存されたイベントを検索可能な状態にすることで、複数のログソースを横断した分析を可能にする。

#### Search Head

アナリストがSPLによる検索、レポート、ダッシュボードなどを利用するためのコンポーネント。

Indexerへ検索要求を送り、得られたデータを分析・可視化する。

今回のラボではIndexerとSearch Headを同一のSplunkインスタンスで構成したが、大規模環境では役割ごとに分離・分散される場合がある。

#### Deployment Server

多数のForwarderを一元管理するための仕組み。

数台程度であれば個別設定も可能だが、数百・数千台規模になると各端末を直接管理することは現実的ではない。

Deployment Serverを利用することで、Forwarderの設定や更新を中央から管理できる。

### ハンズオン

LinuxホストへSplunkとUniversal Forwarderを導入し、CLIやWebインターフェースを利用して設定した。

OSログやWebログをSplunkへ転送し、Splunk側で受信・検索できる状態まで構築した。

手順自体はほとんど指示された内容を順番に実行する形式だったため、難しい調査や判断は必要なかった。

一方で、

**Endpoint / Server  
→ Forwarder  
→ Indexer  
→ Search Head  
→ Analyst**

というログ収集から分析までの経路を実際に触れたことで、これまで利用していたSplunkの裏側を理解することができた。

## Splunk: Dashboards and Reports

Splunkに保存されたデータを整理・可視化し、継続的な監視に利用するための機能について学習した。

これまでの学習では、SPLを利用して必要なログを検索し、その結果から攻撃を調査することが中心だった。

今回は検索結果を一度確認して終わるのではなく、

- レポート
- ダッシュボード
- グラフ
- アラート

などへ発展させ、SOC運用に利用する方法を確認した。

### レポートと可視化

Splunk上で検索結果を利用して分析レポートを作成し、さまざまな形式のグラフへ可視化した。

大量のログをそのまま一覧で確認するのではなく、

- イベント数の推移
- ログイン状況
- 送信元などの偏り
- 特定条件に一致するイベント

などをグラフとして表示することで、傾向や異常を認識しやすくできる。

また、検索を保存して定期的に実行することで、同じ分析を繰り返し手作業で実施する必要を減らせる。

### ダッシュボード

複数の検索結果やグラフを一つの画面にまとめ、継続的な監視に利用するダッシュボードを作成した。

これまでのChallengeでは、

**「問題が起きた後にログを検索する」**

ことが中心だったが、ダッシュボードでは、

**「普段から見るべき情報を整理し、変化や異常を発見しやすくする」**

という使い方になる。

Splunkを調査ツールとして利用するだけでなく、監視基盤として活用する方法を学んだ。

### アラート・UEBA・SOAR

Roomではアラート作成や、UEBA・SOARなど他のセキュリティ機能との連携についても取り上げられた。

ただし、一部の機能は今回利用できる無料版Splunkでは提供されていなかったため、実際に操作するのではなくウォークスルーを通して仕組みを確認した。

概念としては、

**ログ収集  
→ 検知  
→ アラート  
→ 相関分析  
→ インシデント対応  
→ 必要に応じた自動化**

という形で、Splunkを中心としたSOC運用へ発展させることができる。

Splunk Enterprise SecurityやSOARなどを組み合わせることで、単なるログ管理・検索基盤から、検知や対応を含むSOC基盤へ機能を広げられることを学んだ。

## 所感

今日はSplunkを利用したインシデント調査ではなく、

**「SplunkそのものをSOCでどのように構築・運用するのか」**

について学習した。

Setting up a SOC Labでは、Forwarder、Indexer、Search Head、Deployment ServerといったSplunkの構成要素を確認し、実際にUniversal Forwarderからログを取り込んだ。

これまでSplunkを使ってログを検索することは多かったが、そのログがどのように収集され、検索可能な状態になっているのかについて理解を深めることができた。

Dashboards and Reportsでは、検索したデータをレポートやグラフへ変換し、ダッシュボードとして継続的な監視に利用する方法を学習した。

また、無料版では実際に利用できない機能についても、ウォークスルーを通してアラート、UEBA、SOARなどとの連携を確認した。

今回の2Roomを通して、

**ログを集める  
→ 保存する  
→ 検索する  
→ 可視化する  
→ 検知する  
→ 対応につなげる**

というSplunkを利用したSOC運用全体の流れが見えやすくなった。
